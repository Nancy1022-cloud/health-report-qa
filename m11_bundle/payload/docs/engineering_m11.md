# M11：持久任务、有限重试和中断恢复

适用：健康报告项目，M10 PostgreSQL / pgvector 实现之后。单主机、一个 worker；API 与 worker 共用业务数据库、同一份 app 代码和 uploads 持久目录。

## 1. 对外行为

上传页使用异步入口：

| 接口 | 行为 |
| --- | --- |
| POST /api/tasks/upload | 校验文件和成员、保存原件、登记抽取任务，返回 202 |
| POST /api/tasks/reports/{id}/confirm | 登记人工确认后的建索引任务，返回 202 |
| POST /api/tasks/reports/{id}/revisions | 登记带 expected_version 的修订任务，返回 202 |
| GET /api/tasks/{id}?member_id=… | 返回任务状态、尝试次数、调用预留、阶段与终态结果 |
| GET /api/tasks/worker | 查询独立 worker 最近心跳 |

三个提交接口必须提供 Idempotency-Key。相同 key 和内容返回同一任务；key 对应不同内容返回 409。同一成员相同文件的进行中或成功任务可复用；两个成员的文件分别处理。提交确认仍须显式 reviewed=true。

202 表示已接受任务。抽取成功只产生待人工确认的草稿，确认/修订成功后才有新的可查询版本。页面先轮询任务，再重新读取当前报告，避免把历史任务回执当作当前业务版本。

M10 的同步接口继续兼容旧脚本与回归；其事务、幂等和业务版本检查继续执行。这些兼容入口的模型调用不经过 M11 任务预算。M11 的异步保证及调用计数仅适用于 /api/tasks 的提交链路，演示和后续测量均使用此链路。问答暂时仍同步执行。

## 2. 两套状态与两种版本

| 对象 | 状态 / 版本 | 含义 |
| --- | --- | --- |
| 任务 | queued / running / succeeded / failed / superseded | 等待、执行、成功、明确失败、被新处理代次取代 |
| 阶段 | starting、fields、normalized、embedding:哈希、index_prepared、retry_wait、completed 等 | 最近处理位置；完整阶段在 artifacts 中保存 |
| 报告 | draft / confirmed；index_state=ready 或 invalid | 延用 M10 的业务可见规则 |
| 处理代次 | generation | 对某份报告接纳新的不同写入任务时递增，撤销未完成旧任务的提交权 |
| 已发布版本 | reports.data_version | 仅在确认/修订事务成功提交时变化，索引版本与其一致 |
| 一次执行 | execution_token、lease_until | 每次领取任务生成新标识和租约，恢复后旧标识失效 |

重复 key 不会创建新代次；同内容的活跃/成功任务也可复用。不同写入任务取代尚未完成的旧任务时，旧任务记为 superseded，旧报告的已发布版本保持可查询，直到新任务原子提交。

## 3. 数据与提交边界

- processing_tasks：固定输入、处理配置、指纹、状态、总时限、尝试次数和调用预算。
- processing_heads：每份报告当前有效的处理代次与任务。
- processing_receipts：提交 key 对应的任务及请求指纹。
- processing_artifacts：同一任务、同一指纹的已完成阶段结果。
- processing_calls：每次调用预留、结果、真实返回 usage 或 NULL。
- processing_events：领取、阶段保存、重试、恢复、成功等过程记录。
- processing_worker_state：worker 心跳和下一次允许调用的时间。

领取使用 FOR UPDATE SKIP LOCKED。数据库会话锁限制同一 schema 只有一个生产 worker。报告写入保持与 M10 相同的报告锁顺序，领取与心跳使用短事务；外部模型请求在事务之外执行。

每次保存阶段、预留调用和提交结果，都检查任务 running、token 相同、租约未过期、总时限未过期，以及 head 中的任务和代次仍匹配。最终事务同时保存正文、指标、索引、修订来源与任务成功状态；提交前再次检查时限。业务写入成功而任务仍需重放的可避免窗口由这一事务关闭。

原件先完整写入，再登记任务。抽取阶段在数据库保存后，用稳定报告 ID 原子生成草稿文件，然后在数据库登记来源与任务成功。中断可能留下未引用文件，恢复复用同一 ID 和已保存结果；不自动清理可能仍被引用的原件。这里保证进程中断恢复，未宣称数据库与文件系统具备跨系统事务或断电级一致性。

## 4. 重试、租约、额度与硬时限

默认策略如下，受控验收会用更短租约缩短等待。

| 参数 | 默认值 | 计数范围 |
| --- | ---: | --- |
| 最大尝试次数 | 3 | 同一任务所有领取和中断恢复共用 |
| 最大调用预留 | 128 | 同一任务所有模型尝试、重试和可能重发共用 |
| 总时限 | 600 秒 | 从提交开始，包括排队、处理和重试等待 |
| 租约 / 续租间隔 | 15 / 3 秒 | 父 worker 续租，过期后旧执行失效 |
| 单次模型请求超时 | 最多 30 秒 | 同时受任务剩余时限限制 |
| 模型调用最小间隔 | 0.25 秒 | 时间保存在数据库，进程重启不会归零 |
| 退避 | 1、2、4…秒，上限 8 秒 | 自动重试不创建新任务或重置预算 |

可通过环境变量 M11_MAX_ATTEMPTS、M11_MAX_CALLS、M11_TASK_TIMEOUT、M11_CALL_INTERVAL 在给定范围内设置策略。本阶段默认即可。默认 128 是请求次数上限，不是金额或 Token 上限；真实调用预算测量留到 M12。

只有网络连接失败、请求超时和选定的临时 HTTP 错误自动重试；401/403、识别出的余额或配额错误、输入/质量/版本错误、损坏的模型输出均明确失败。SDK 自带重试关闭，重试由任务层统一控制。持续失败在尝试次数、调用预算或总时限中的任一边界处结束。

父 worker 启动子进程处理任务，并持续续租。子进程卡住时，父进程在总时限或丢失租约后终止它。worker 容器被终止后，任务仍在数据库，下一 worker 在租约过期后恢复或明确失败。GET 状态也会收敛过期任务。主动关闭 worker 后，尚未完成的任务不会凭空变成成功。

失败后的同 key 提交仍返回原失败任务。修正问题后主动重新提交、使用新 key，才是有新预算的新任务；页面在取得失败终态后会为下一次人工提交生成新 key，不做无限自动重建。

## 5. 外部调用窗口与未知用量

调用前先登记预留，之后才发送请求。若在预留后、请求前中断，额度可能被保守多计一次；若模型已经返回、结果还没保存就中断，恢复可能重发。无法从本地可靠判断供应商是否执行过的预留记为 unknown，不退还预算，也不宣称外部调用恰好一次。

阶段结果和该次调用的已知 usage 一起提交；该阶段已保存时，恢复从缓存继续。usage 缺失保留 NULL。调用失败但服务端可能已经计费、或预留后其实尚未发送时，都不能把未知费用记作零。M12 应分别统计预留、已知成功/错误/未知和 usage 覆盖率，不能把阶段缓存中的历史用量重复加到实际调用数里。

## 6. 验收证据

离线检查验证策略、文件完整性、阶段复用、SDK 重试设置和 HTTP 契约。真实 PostgreSQL 探针在独立 schema 中运行合成任务，覆盖：重复提交、成员范围、并发领取、单 worker、进程直接退出、抽取与索引阶段复用、提交中途失败、旧代次/旧 token、临时/持续/永久错误、共享调用额度、排队时限、监督进程强制终止、持久化限速。

“进程中断”用验收子进程直接退出演示，真实等待租约过期后恢复；有一个旧 token 检查和排队超时检查直接修改隔离测试表的时间，只验证对应边界，单独记录。为加快验收，重试等待会在隔离表中推进，不据此报告真实退避耗时。旧任务迟到使用阻塞中的执行和先完成的新任务，验证最终可见版本。

同时运行 M10 一致性回归和旧问答/工具契约探针，核对共享业务表前后哈希，清理临时 schema 和合成文件。本地结果不能外推成生产可用性；测试函数数、场景数、真实模型评测数分别报告。

M11 迁移只新增任务表。在副本演练时复制九张既有业务表的字段、索引、检查约束、身份列与数据，不重新创建既有业务外键；M11 新增外键实际创建并检查。演练与正式迁移均核对既有业务行未被修改，保留迁移校验和与重复执行结果。

## 7. 运行、重启与边界

运行：`docker compose -f compose.yaml -f compose.m11.yaml up -d app worker`。只重启 worker：`docker compose -f compose.yaml -f compose.m11.yaml restart worker`。查看日志使用同一组 -f 参数；环境或策略有修改时用 up -d --force-recreate worker 重新创建容器。

app 和 worker 必须同时使用本阶段代码，uploads 需要持久挂载。不要运行两个 worker，也不要使用 docker compose down -v 删除数据库卷。已升级后先停止接收新任务、保留当前数据库与文件，再按升级前备份恢复到新库验证；不可只覆盖 Python 代码而遗留未完成任务。

首版不包括分布式队列、高可用、多主机文件同步、用户认证或真实医疗诊断。member_id 是已有的本地业务隔离维度。问答与旧同步入口的模型调用不在 worker 限速范围内；后续性能实验需要固定并分别报告这些链路。
