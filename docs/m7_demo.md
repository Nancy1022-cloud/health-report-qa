# M7 演示与讲解

先跑完冻结后的首轮验收，再练习下面的案例。演示使用合成数据。

## 1. 精确指标查询

选定 `m7_member_a`，报告范围为 `m7_a_20261015`，提问：“验收甲10月15日的空腹血糖是多少？”

期望：5.30 mmol/L、2026-10-15，以及真实 `metric:` 引用。打开本次 `trace_url`，说明模型生成了哪些工具参数、程序如何读取已确认指标。

## 2. 跨报告组合查询

选定 `m7_member_a`，报告为 `m7_a_20260115` 和 `m7_a_20261015`，提问：“对比这两份报告的空腹血糖数值，并分别列出两份报告的备注。”

期望：6.30 与 5.30 mmol/L；甲01 与甲06对应的备注均有原文证据。检查工具查询是否覆盖两份报告。只有实际触发 `origin=evidence_controller` 的 `tool_request` 才展示为本次补检索；`supplemental_calls=0` 是正常路径，不能声称补检索一定发生。

## 3. 缺失资料

选定 `m7_member_a`，报告为 `m7_a_20261015`，提问：“这份报告的尿酸具体数值是多少？”

期望：`insufficient`，说明未记录，不编造数值。若实际返回503或504，应按工具或模型故障解释，不能说成“成功拒答”。

## 4. 上传与确认

打开 `/upload`，选择妈妈，上传 M6 合成PDF或同内容图片。对照原件核对日期、三项数值与单位；确认后再问报告的建议或数值。

保留“未确认时不可查、确认后可查”的过程；演示页面提交的 `report_ids` 为当前上传ID。相同文件重复上传产生新的报告ID，不能把旧ID的日志当作本次结果。

## 2～3分钟项目介绍提纲

我从零实现了一个按家庭成员管理的报告查询原型。用户上传文件后先核对候选字段，系统再保存指标并建立报告索引；问精确数值时查询结构化记录，问结论与建议时检索原文，组合问题可以调用多种工具。

检索保留固定切分与向量基线，再逐项比较章节切分、中文全文检索与RRF。工具调用由模型选择与生成参数，后端校验成员、报告与日期范围，并用程序计算可比较记录的变化。证据缺口允许定向补检索一次，引用必须来自本次实际获取的证据，所有分支共享预算。

评测时报告本机实际得到的正确题数、完整证据覆盖、耗时与失败类型。讲清一个成功案例和一个真实失败案例，并说明下一步针对哪个错误改进。不要把未实现的重排、长期记忆或论文Self-RAG写进介绍。
